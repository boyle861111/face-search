## 已完成項目細節

**1. GPU 失敗退回 CPU** — `make_session` 建立 DirectML session 失敗時改建 CPU session；`_compute` 把「讀檔」和「推論」分開，推論錯誤不再被當成讀取失敗寫進快取，而是拋回 `_run`：若正在用 GPU，就記 log、提示使用者、以 CPU 重建模型並重試該張。→ 原本驅動不相容會整個報錯，或每張照片都被記成「無法讀取」且永久快取。→ 使用者會看到「已自動改用 CPU」提示，搜尋繼續。→ 9d03343

**2. 停止狀態** — `done` 訊息帶 `stopped` 旗標；狀態列顯示「已停止」，訊息區顯示「已中途停止（已處理 n / N 張）」。→ 原本按停止後仍顯示「完成」。→ 9d342c6、7cc61e1

**3. 讀取失敗不快取** — 載入快取時排除 `error` 不為空的紀錄，下次會重新分析並覆蓋舊紀錄。→ 雲端尚未下載、被占用的檔案以前會永遠被跳過。→ 7cc61e1

**4. 白話錯誤** — 新增 `friendly_error()`：權限不足、磁碟空間不足、記憶體不足、路徑過長／找不到路徑、找不到檔案各有中文建議；其他錯誤顯示簡短訊息；完整 traceback 由 `log_exception()` 寫入 `face_search.log`，錯誤視窗會告訴使用者 log 位置。已用假例外做邏輯測試。→ a955792

**5. 資料存放位置** — 啟動時測試 exe 旁是否可寫，不可寫就用 `%LOCALAPPDATA%\FaceSearch`（faces.db、settings.json、face_search.log）。模型仍優先使用 exe 旁附帶的檔案。→ 2349eda

**6. 完成摘要** — 狀態列顯示「完成｜A 命中 x／邊緣 y｜…」；有結果時詢問是否開啟結果資料夾；0 命中時訊息區與彈窗建議調低門檻（例如 0.40）或提高解析度（例如 1024）。→ 4e83efc

**7、8. 目標資料夾檢查** — 每個子資料夾沒有可用樣本時顯示「目標 X 無可用樣本，已略過」；樣本少於 3 張附加提醒。目標資料夾沒有子資料夾但有照片時，以資料夾名稱當作一位目標並說明多人時的結構。→ 7924c42

**9. 首次使用引導** — 啟動時若目標資料夾不存在，訊息區顯示 4 步驟說明；新增「建立目標資料夾」按鈕（建立 `目標\人名1`，已有子資料夾則只開啟）。→ 4aba9e9

**10. 設定說明** — 「相似度門檻 ⓘ」「偵測解析度 ⓘ」加上灰字說明與滑鼠提示（含建議值）；勾選項目移到第二列避免設定列太長。→ 56372ed、788ee8b

**11. 結果清單** — 點欄位標題排序（相似度預設由高到低，再點反向，標題顯示 ▲▼）；上方「顯示目標」下拉可只看某人。搜尋中新結果會即時加入。→ 334dfc5

**12. 預覽** — 預覽時用 JPEG draft 以接近視窗大小解碼，先縮小再轉正。測試：6000×4000 JPEG 約 0.01 秒；EXIF 旋轉方向正確。→ 7dd0606

**13. 版本號** — 程式內 `APP_VERSION = "dev"`，build.yml 打包前改寫為手動輸入版本、tag 名稱，或 `dev-<commit 前 7 碼>`。→ 5592023

**14. 快取清理** — 完整跑完（非中途停止）後，刪除「位於本次照片資料夾內、但檔案已不存在」的快取紀錄；其他資料夾（例如外接硬碟未插上）的快取不動。已用暫存資料庫測試。→ 5520fb2

**15. HEIC** — 有安裝 `pillow-heif` 時註冊 HEIF 解碼並加入 `.heic/.heif`；沒安裝時自動略過，不影響其他功能。build.yml 安裝 `pillow-heif` 並 `--collect-all pillow_heif`。需實機驗證。→ 5c407af

**18. README** — 使用步驟、資料夾結構、支援格式、設定建議值表、輸出結構、快取／設定檔／log 位置、開發者說明。→ d0f6e6a
